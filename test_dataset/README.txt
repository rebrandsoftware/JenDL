Meta-analysis Coding Instructions

In the test dataset zip file are four distinct files:
1) The README file (the file you are reading)
2) Construct definitions
3) test_articles.csv
4) test_submissiontemplate.csv

1) The README File contains the overview of the data and some instructions about using the files. Finish reading this file before accessing the other data files to know how they fit in with the competition. The test dataset contains multiple studies focused on different construct relationships. Unlike the training data, there are many constructs being examined beyond just trust and life satisfaction. For the test set, your model has to adapt to many different construct definitions and relationships. All pairs are being studied cross sectionally, so the coded effect from papers must always be at the same temporal level (e.g., Time 1 X -> Time 1 Y; Time 2 X -> Time 2 Y; Never Time 1 X -> Time 2 - Y). All pairs of the same X and Y constructs are studying the same research question (You can assume the meta-analytic research question for the test phase is always some form of, "What is the bivariate association between X and Y"). You can modify the research question as you see it as along as it is consistent for all articles that study the same construct pairs.

2) The Construct definitions file is intended to provide clear guidance on the meta-analysis research questions and variables used in the test  dataset. It is intended to be equivalent to how a researcher might describe their research question, and it reflects the variables included in the actual meta-analysis coding sheet. Note that there are many different constructs. Which construct pair is examined is specified in the article list csv file.

For your meta-analysis pipeline, you must create a system that accepts a research question, a predictor variable description, and an outcome variable description, and a pdf. From those inputs, your pipeline must be able to extract all bivariate statistics related to those from the pdf, which may be found in tables, figures, or within the text. Your pipeline must be generalizable and not custom fit on a specific research paper. You are free to modify the research question, predictor variable, and outcome variable descriptions as you see fit, but the research question, predictor variable description and outcome variable description must be same for papers studying the same construct pairs. The rest of the model but be unchanged across papers. The pipeline must find all of the relevant effect sizes from the study, and convert them to Pearson's r and code them in the direction that construct 1 and construct 2 are written (if needed). The output of the pipeline must be an aggregate effect size, which is simply the average of relevant effect sizes found.

3) The Test Phase Articles file provides a list of articles for you to code with your pipeline and receive feedback on its performance. Unfortunately, the organizers of the competition are not allowed to share the original pdf, so the articles must be downloaded by your team. The organizers, however, have restricted the articles to be ones where a pdf of the article can be located via Google Scholar. Each article has a study number associated with it, which is important for submitting pipeline attempts to the leaderboard.

4) The Test Submissions Template file is a fillable csv that shows what you would submit to the leaderboard (with the aggregate effect sizes filled in each blank cell next to the study number. You will receive an error score (lower is better), and your highest submission will appear on the leaderboard.
